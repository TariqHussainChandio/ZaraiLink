# P2: Expo migration and how each claim was proven (2026-09-22)

Phase P2 moved the app to Expo SDK 57 with generated native code (`android/` is now built from `app.config.ts`,
not checked in), replaced two native libraries and the environment loader, and added an Android build job to CI.
Everything below was run on **one Android 16 emulator against a local Supabase stack and a local API**, and the
pipeline then ran green on GitHub as pull request 3. It has not been run on a physical phone or on an older Android
version. Those are the remaining proofs, and they need you.

A separate verifier agent re-ran the checks and tried to break the work. It found two real problems and several
overclaims. All are fixed and re-proven, and the section "What the independent check found" lists them.

## What changed

- **Toolchain:** Expo 57.0.24, React Native 0.86.2 to 0.86.3, TypeScript 5.9 to 6.0, ESLint 8 to 9, Prettier 2 to 3.
  `app.json` became `app.config.ts`. Babel, Metro, Jest, and the tsconfig now use Expo's presets.
- **Configuration:** `react-native-config` and its build-time `.env` step are gone. `src/config/env.ts` reads
  `EXPO_PUBLIC_*` variables and validates them with zod at startup. A bad value stops the app with a message that
  names the variable. Eight tests cover it.
- **Libraries:** `expo-haptics` and `expo-image-picker` replace the two React Native libraries. The app now has its
  own `PickedPhoto` type instead of the picker library's asset type. Five packages moved *down* to the versions
  Expo SDK 57 was tested with (gesture-handler 3.2 to 2.32, async-storage 3.1 to 2.2, screens, safe-area-context,
  svg). The hand-written AsyncStorage test mock is replaced by the one the package ships.
- **Native project:** generated. Permissions, SDK levels, R8, and `allowBackup` live in `app.config.ts`.
- **CI:** a new `android` job (Expo doctor, prebuild, debug and release builds, Gradle cache) and Dependabot rules
  that leave the SDK-pinned packages alone.
- **Lint:** ESLint 9 with Expo's config. That config alone dropped 66 rules the old one enforced, so 55 of them
  are restored with their old severities (the jest, React Native, deep-import, shadowing, `eval`, `debugger`, and
  fall-through checks among them). Each was proven by planting a violation. Findings are unchanged at 16, and the
  baseline is lower by one unused suppression removed from `Skeleton.tsx`.

Not restored: deprecated Node-only rules, and the eslint-comments plugin, which the reality gate and `reportUnusedDisableDirectives` already cover |

## Behaviour that is different

| Area | Before | Now |
|---|---|---|
| **Taking a photo** | No permission prompt | Android asks for the camera the first time. Refusing returns you to the form quietly (checked on the debug and the release build). The photo is no longer also copied into the gallery. On Android 9 and older the camera also asks for storage access (the library requires it; not tested here) |
| **Release permissions** | Internet, vibrate | Adds camera and legacy write-storage (up to Android 12L only). Everything else Expo adds is blocked: overlay windows, legacy read-storage, microphone. Vibrate stays: the old library needed it too, and I cannot feel haptics on an emulator to prove it is now unnecessary |
| **Haptics** | System touch-feedback setting respected | Still respected, through a different Android call. Success uses the confirm feedback (Android 11 and later) and falls back to the light tap. Unit-tested; nobody has felt it on a phone |
| **Stored session** | Kept in AsyncStorage 3 | AsyncStorage 2.2 uses a different storage backend, so **an existing development install loses its stored session and preferences** and you sign in again. The app was never released, so no user is affected |
| **Edge to edge** | The old opt-out, ignored by Android 16 | Always on, because SDK 57 has no switch. Identical on the Android 16 emulator. **Not checked on Android 15 and older** |
| **Deep links** | Only `zarailink://reset-password` | Any `zarailink://` link, plus `exp+zarailink://` for the developer tools. Navigation ignores links it has no route for, but the reset handler acts on any link that carries a `code` parameter, whatever its host |
| **Environment file** | `SUPABASE_URL`, `API_BASE_URL`, and so on | `EXPO_PUBLIC_` prefix on all four. **Your local `.env` must be renamed** |
| **Launcher icon and splash** | Android robot | Expo's defaults. The app never had a brand icon |
| **Unit tests** | Ran as iOS (Jest's default) | Run as Android, the only shipped platform. One switch needed an explicit label to be found |
| **Cleartext HTTP** | Explicitly off in release | Off by default at target API 36. A release build refused `http://10.0.2.2` with the system's own error. Predictive back is now explicitly off in the manifest |

## What I found that belongs to later phases

- **The `onNewIntent` override was not needed.** The plan said Expo's template makes it unnecessary. I doubted that,
  built a plugin to restore it, then removed the override from a control build and tested again: the link was
  delivered either way. My first tests were invalid, because a made-up reset code is rejected locally and shows
  nothing. The plugin is deleted. The lesson is in `AGENTS.md`.
- **A bad or expired reset link shows the user nothing.** The handler only catches thrown errors, and supabase-js
  returns them instead. Phase P4 replaces the flow with an emailed code.
- **The farmer and dealer home screens spin forever when any request fails.** They are one dashboard component whose
  loading code has no error handling. The farmer's failure is defect N2 (P5a). **The dealer's cause is not found:**
  the backend logged no error, so it is likely one of the direct database queries or a response the screen cannot
  read. Nothing in P2 touches that screen. It needs an error state (P7) and a look at the failing call (P5a). The
  expert's screen fails cleanly with a retry button. Because the disease advisory is reached from the farmer home
  screen, **it is unreachable for a farmer while this stands**.
- **Sign-in errors show raw exception text** (`java.net.UnknownServiceException: CLEARTEXT ...`) to the user. P4.
- **The status-bar clock is white on light screens.** The app never sets a bar style. Same theme before and after,
  so this predates P2. P8.
- **Release builds carry the developer scheme `exp+zarailink://`, and Expo's template adds the JitPack repository.**
  Nothing in the module cache came from JitPack, but that is not proof. Both are release-hardening items for P12.
- **Formatting is not enforced and never was.** 263 of 316 source files differ from `.prettierrc.js`. Enforcing it
  means one reformat commit that buries `git blame`, which is your call.
- **ESLint 9 is in maintenance.** ESLint 10 exists, but `eslint-plugin-react` and `eslint-plugin-import` (both used
  by Expo's config) do not support it yet.
- **JavaScript `console` output never reaches `adb logcat`** in this React Native version, so an unhandled
  rejection in a release build is invisible. Sentry (P7) is the way to see them.
